# Roadmap

Commercial-scale coverage is a direction, not a promise. Each capability ships
only when it is implemented, tested and documented, including its
limitations. Detection quality claims require the evaluation methodology in
[docs/detection/testing.md](docs/detection/testing.md).

Status legend: **done** (implemented and tested) · **next** (active
milestone) · **planned** (designed or scoped) · **research** (needs
investigation before design).

## Known-limitations work plan

[Known limitations](docs/known-limitations.md) are being addressed in
phases. Each phase ships with tests and doc updates, and moves items off
that list.

| Phase | Theme | Status |
|---|---|---|
| 1 | Scan robustness: stall watchdog, whole-scan limit, full-path symlink safety, de-duplication, atime, MSRV | **done** |
| 2 | Archive scanning (ZIP first) with decompression-bomb limits | **done** (ZIP) |
| 3 | Content trust: rollback and expiry protection, key rotation, project key procedure | **done** (keys to be generated by the owner) |
| 4 | Remediation completeness: restored-file allow-list, audit-log anchoring, process termination | **done** |
| 5 | Linux persistence and integrity checks | **done** |
| 6 | Heuristics | **done** (PE rules await a Windows measurement) |
| 7 | Service, authenticated IPC, privilege separation, scheduling | **done** (Linux; Windows transport in 8) |
| 8 | Windows parity: quarantine store, locked files, file IDs, service transport | next |
| 9+ | Real-time protection, updater, signed releases, GUI, detection evaluation | research |

Shipping real signatures or rules is a content-sourcing decision (licensing),
not a code change, and is tracked separately.

## 1. Scanner foundation: done (0.1.0)

* done: workspace, core data model, versioned JSON report
* done: traversal with symlink policy, excludes, depth/size limits, same-filesystem option
* done: hardened open (no-follow, non-blocking, handle re-verification)
* done: SHA-256, bounded concurrency and memory, cancellation, progress
* done: CLI with human and JSON output, sanitised terminal output
* done: unit, integration and CLI tests; parser fuzz harnesses
* done: per-file time limit, stall watchdog, whole-scan time limit ([ADR-0009](docs/architecture/decisions/0009-stall-watchdog.md))
* done: symlink-safe full-path opens on Linux, de-duplication under `--follow-symlinks`, no atime updates where permitted
* done: MSRV 1.93 declared and verified in CI

## 2. Signature and rule engine: mostly done

* done: exact SHA-256 database format v1 with strict validation
* done: minisign-signed databases and rules, verified before parsing ([ADR-0007](docs/architecture/decisions/0007-content-signing.md))
* done: YARA-X in `warden-yara` ([yara.md](docs/detection/yara.md))
* done: single bounded read per file shared by detectors; per-worker detector state ([ADR-0006](docs/architecture/decisions/0006-content-access-and-time-limits.md))
* done: ZIP archive scanning with bomb limits ([archives.md](docs/detection/archives.md))
* planned: further archive formats (7z, tar/gzip, CAB, MSI/OLE) after parser review
* done: signed content bundles with rollback, expiry and keyring revocation ([content-trust.md](docs/security/content-trust.md))
* planned: automatic updater (TUF) with threshold signatures
* done: PE and ELF structure, name, script and location heuristics ([heuristics.md](docs/detection/heuristics.md), [ADR-0017](docs/architecture/decisions/0017-file-heuristics.md))
* planned: measure PE heuristics on a Windows corpus, then decide which run by default
* research: pattern/family signature format

## 3. Quarantine and remediation: done on Linux

* done: store, restore, delete, hash-chained audit log, journaled crash recovery ([quarantine.md](docs/security/quarantine.md))
* done: automatic policy (confirmed malware hash matches only, never system directories)
* planned: Windows store (DACL-hardened, by-handle operations)
* done: allow-list for restored files; audit log anchored in syslog/journald; stopping processes running a quarantined file ([ADR-0014](docs/architecture/decisions/0014-remediation-completeness.md))
* planned: persistence cleanup (the Phase 5 inventory identifies what to remove)

## 4. Background service: done on Linux

* done: `abyssal-wardend` with jobs, schedules and persistent history ([ADR-0018](docs/architecture/decisions/0018-service-and-ipc.md), [user guide](docs/user/service.md))
* done: authenticated local IPC with an authorisation matrix ([privilege model](docs/security/privilege-model.md))
* done: scans in reduced-privilege, killable child processes; hardened systemd unit
* done: automatic comparison of the quarantine audit log with the journal
* planned: seccomp/landlock for scanner children; polkit
* planned: Windows service (SCM) and named-pipe transport (Phase 8)

## 5. Windows security integrations: started

* PE analysis, Authenticode verification
* done: persistence inventory: Run keys, Winlogon, AppInit_DLLs, IFEO, services, scheduled tasks, Startup folders (live system; [ADR-0016](docs/architecture/decisions/0016-package-trust-self-integrity-windows.md))
* planned: WMI subscriptions, COM hijacks, shortcut targets, offline hives
* planned: driver cross-view, hidden processes
* AMSI provider, ETW telemetry, minifilter-based on-access scanning ([platform notes](docs/platform/windows.md))

## 6. Linux security integrations: research

* done: package integrity checks through rpm/dpkg ([system-checks.md](docs/detection/system-checks.md))
* done: persistence inventory: systemd, cron, `ld.so.preload`, shell profiles, environment, XDG autostart, PAM, SSH keys, `rc.local`, udev ([ADR-0015](docs/architecture/decisions/0015-system-checks.md))
* done: SysV init, `at`, generators, `modules-load.d`/`modprobe.d`, motd, SSH rc, initramfs and GRUB hooks, eBPF program inventory, boot integrity (Secure Boot, lockdown, command line, `/boot` permissions)
* done: package files hashed by Abyssal Warden (native dpkg database reader); scanner self-integrity check
* planned: verification against signed distribution repository metadata; TPM event log
* planned: ELF analysis
* fanotify-based on-access scanning; eBPF telemetry ([platform notes](docs/platform/linux.md))

## 7. Rootkit and persistence detection: Linux done

* done (Linux): kernel module cross-view, taint flags, hidden-PID sweep, deleted executables in writable locations
* done: limitations of in-OS detection documented; offline inspection with `system-check --root`
* research: memory-based and eBPF-based checks; Windows equivalents

## 8. Real-time protection: research

Depends on milestones 4-6. Requires platform-supported mechanisms
(minifilter drivers on Windows, fanotify permission events on Linux), not a
directory watcher.

## 9. Offline scanning: partly done

`scan` on a mounted image, and `system-check --root` (links resolved inside
the image) work today. Planned: a documented trusted-boot-media workflow.

## 10. GUI: planned

egui is the provisional choice ([evaluation](docs/architecture/gui.md)).
Unprivileged, and talks only to the service over authenticated IPC.

## 11. Testing and release hardening: ongoing

* done: CI gates for fmt, clippy, tests (Linux and Windows), rustdoc and cargo-deny
* planned: scheduled fuzzing campaigns and a corpus in CI
* planned: reproducible builds, signed release artifacts, SBOM
* planned: detection evaluation harness with published methodology
